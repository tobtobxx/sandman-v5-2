How topic archiving works today

Context for tobtobxx/sandman-v5-2#8 — “Archive topics after 24h and when no card is open. Allow pinning and unarchiving.” State of main at 4ec7dca.

Short version
  • Topics have two states, active and archived. There is no “deprecated” state for topics (the only superseded status belongs to memory claims, unrelated).
  • Archiving is automatic, done by the tidy-up job: subject topics after 14 quiet days, conversation topics after 1 quiet day, and only if the topic has no open cards and no open questions.
  • Any new message in a topic un-archives it. There is also an Undo on the review notice and a PATCH /topics/:id.
  • No pinning. No archived list in the UI. No agent-side search over old topics besides the router's FTS lookup.
  • Catch: tidy only runs after a memory consolidation, which only happens if there are pending facts. On quiet days nothing gets archived at all.

3. When tidy actually runs

src/server.ts:282-291 — a 60 s interval:

TriggerRuns tidy?
≥20 pending factsYes, after consolidate()
Hour is 03:xx and ≥1 pending factYes, once per night
03:xx but 0 pending factsNo
POST /tidyYes (manual)
This is probably the source of “it doesn't seem to archive”: tidy is chained to consolidation, and consolidation is skipped when nothing is pending. DESIGN.md:800 says tidy runs “right after each nightly consolidation”, which the code follows literally — but a night with no new facts means no tidy. For a 24 h rule it would need its own schedule (or at least run at night regardless of pending facts).

7. Side notes

  • Short windows + implicit reactivation. With 24 h, a late card result or reminder firing into an archived topic will pop it back to active (via addMessage). Probably desired, but it means “archived” is soft.
  • Summary quality matters for recall. The only index over topics (topics_fts) is title + rolling summary. If archiving becomes aggressive, dig-up quality depends on that summary; messages themselves aren't in topics_fts.
  • Notice noise. Each subject archive creates a review item. At 24 h that becomes a daily stream; the conversation-topic rule already avoids this by being silent.
  • Pinning would slot in at one spot: the candidate query in tidy.ts:11 (plus a column in db.ts:13-15 and a PATCH field in server.ts:63).
  • Merged topics reuse archived + merged_into; they're excluded from lists and routing, and there's no un-merge.
